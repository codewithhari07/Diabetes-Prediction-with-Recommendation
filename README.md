# Diabetes Prediction with Recommendations

A Flask web application that estimates diabetes risk from eight health measurements and displays lifestyle recommendations. It also includes an optional AI health assistant that answers questions using a small, locally stored FAISS knowledge index and Google Gemini.

**Demo:** [Diabetes Prediction](diabetes-prediction-with-recommendation-production.up.railway.app)

> **Health information:** This project is for learning and demonstration. Its output is not a medical diagnosis and should not replace advice from a qualified healthcare professional. Do not make health decisions based only on this application.

## Features

- Collects pregnancies, glucose, blood pressure, skin thickness, insulin, BMI, diabetes pedigree function, and age.
- Scales the submitted measurements and applies the saved classification model and decision threshold.
- Shows a risk category, probability, and rule-based diet, exercise, Ayurveda, and warning suggestions.
- Provides an AI question-and-answer interface with retrieved context from the bundled FAISS index.
- Runs as a Flask app locally or in a Docker container.

## How it works

The Flask app loads `model.pkl`, `scaler.pkl`, and `threshold.pkl` when it starts. The prediction form sends its eight measurements to `/predict`. The app scales them, gets the model's positive-class probability, and compares that value with the saved threshold. The notebook saves a threshold of `0.2`.

Recommendations are generated by simple rules in `utils/recommend.py`. When a user asks a question from the results page, `/chat` retrieves up to three matching passages from `vector_db/`, then sends the prompt and context to Gemini (`gemini-2.5-flash`). The sentence-transformer embedding model is downloaded from Hugging Face when the app starts.

## Run locally

### Requirements

- Python 3.11
- Internet access on first startup so Hugging Face can download the embedding model
- A Google AI API key for the Gemini chatbot

Create and activate a virtual environment, then install the pinned dependencies:

**Windows PowerShell**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

**macOS/Linux**

```sh
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```dotenv
GOOGLE_API_KEY=your_google_ai_api_key
```

Start the Flask app:

```sh
python app.py
```

Open <http://127.0.0.1:5000>. The chatbot requires a valid `GOOGLE_API_KEY`; keep the key private and out of source control. The app imports the chatbot and retrieval components during startup, so configure the key and allow the Hugging Face model download even when you only plan to try predictions.

## Run with Docker

Build the image from the repository root:

```sh
docker build -t diabetes-prediction .
```

Run the container locally:

```sh
docker run --rm -p 8000:8000 -e GOOGLE_API_KEY=your_google_ai_api_key diabetes-prediction
```

Open <http://localhost:8000>. The container runs Gunicorn and listens on port `8000` by default. It uses the hosting platform's `PORT` environment variable when one is provided. For deployment, build from this repository's Dockerfile, set `GOOGLE_API_KEY` in the platform's environment/secrets settings, and let the platform supply `PORT`. The host needs outbound internet access at startup to download the Hugging Face embedding model.

Free hosting services have different memory, image-size, and sleep limits. This image includes PyTorch, FAISS, and sentence-transformer dependencies; check that the selected service can run the resulting image. The actual image build requires Docker Engine to be running.

## API routes

| Route | Method | Purpose |
| --- | --- | --- |
| `/` | `GET` | Displays the prediction form. |
| `/predict` | `POST` | Accepts the form measurements and renders the prediction and recommendations. |
| `/chat` | `POST` | Accepts JSON such as `{"question": "What is diabetes?"}` and returns an AI answer and retrieved sources. |

The chat route returns JSON with `answer` and `sources` fields. It currently receives no patient measurements or prediction as chat context.

## Model and data

The notebook uses the `Outcome` column in `diabetes.csv` as its target (`0` for no diabetes and `1` for diabetes). It explores several classifiers and saves the XGBoost model, fitted scaler, and threshold as pickle files. The web app expects these artifacts and the prebuilt FAISS index to remain at the paths shown in the project structure.

Pickle files can execute code when loaded. Only use model and vector-index artifacts that you trust. The included dataset and model are for demonstration and are not a substitute for clinical validation.

## Troubleshooting

- **Missing Google API key:** Add `GOOGLE_API_KEY` to `.env` for local use or to the hosting service's environment settings.
- **Hugging Face download errors:** Check outbound network access and allow the first startup to finish downloading the embedding model.
- **Missing model or index files:** Confirm `model.pkl`, `scaler.pkl`, `threshold.pkl`, and both files in `vector_db/` are present in the project/container.
- **Container does not start:** Confirm Docker Engine is running locally and that the deployment service provides its assigned port through `PORT`.
